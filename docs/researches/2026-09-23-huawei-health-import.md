# Research: импорт данных из Huawei Health (#501)

Дата: 2026-09-23

## TL;DR

Официального «пользовательского» API для выгрузки собственных тренировок из Huawei Health не существует — Health Kit это партнёрская программа для приложений-разработчиков (OAuth + регистрация юрлица/DUNS в AppGallery Connect), а не self-service экспорт. Прямого моста Huawei Health → Health Connect (Android) тоже нет — экосистемы HMS и GMS не связаны на уровне ОС. Самый дешёвый рабочий путь для пользователя с Huawei — сторонний синхронизатор **Health Sync** (Android, платный, ~£2–3 разово) в связке HMS Core → Health Connect → уже существующий канал Botkin `POST /android_health_v1`; если он окажется на HMS-only устройстве без Google-сервисов (например, Watch GT-класса телефон), единственный рабочий вариант — ручной запрос данных через Huawei Privacy Center (ZIP-архив) и конвертация HiTrack-файлов инструментом **Hitrava** (открытый код, активно поддерживается), что для пожилого пользователя неудобно и требует помощи. Доработка кода Botkin для этого сценария не нужна на первом этапе — оба пути используют существующие каналы.

## Что нужно узнать у пользователя (блокирует выбор пути)

- **Модель телефона**, на котором стоит Huawei Health: Android с сервисами Google (Google Play присутствует) / Huawei без GMS (только AppGallery, например HarmonyOS или старый EMUI-телефон) / iPhone.
- Готовность поставить и настроить ещё одно Android-приложение (Health Sync), либо предпочтение разового ручного экспорта раз в месяц/квартал.

В issue #501 и комментариях этого не зафиксировано — только факт «пользуется часами и приложением Huawei Health, тренировки вручную».

## Разбор по вариантам

### A. Официальный Huawei Health Kit
Health Kit — программа для приложений-партнёров, доступ через AppGallery Connect: разработчик регистрируется (individual или company; для company — DUNS/бизнес-лицензия), получает одобрение на использование Health Kit (отдельное service agreement), далее пользователь даёт OAuth-разрешение приложению-партнёру, и то читает/пишет данные через Cloud API. Это **не** механизм «пользователь сам скачивает свои данные» — нужен зарегистрированный сторонний сервис-провайдер. Мы такой сервис не запускали и делать это ради одного пользователя семьи избыточно (1-2 дня верификации + ревью + поддержка OAuth-инфраструктуры).

### B. Мост Huawei Health → Health Connect (Android)
Подтверждено несколькими источниками: нативной интеграции нет — HMS (Huawei Mobile Services) и GMS (Google Mobile Services) работают как отдельные экосистемы без OS-уровня моста, начиная с 2019 года (санкции). Единственный путь на Android — сторонние приложения-мосты (Health Sync и аналоги), которые читают Huawei Health через HMS Health Kit SDK (если телефон это позволяет) и пишут в Health Connect. Ограничение: HMS-only устройства (например Huawei-часы без Google-сервисов на телефоне) не смогут быть прочитаны мостом, работающим через Health Connect/GMS-путь.

### C. Мост Huawei Health → Apple Health (iOS)
Приложение Huawei Health в App Store официально заявляет синхронизацию в Apple Health (HealthKit), включая тренировки. На практике — множественные жалобы пользователей на форумах Apple Community и HUAWEI Community именно на то, что **шаги/пульс синкаются, а тренировки — нет или с задержками/пропусками**, особенно после обновлений iOS. Это уже канал, который Botkin умеет принимать (`/apple_health_v2`), доработки не нужны — но надёжность самого моста под вопросом, нужно проверять фактически на устройстве.

### D. Health Sync (сторонний мост)
Health Sync (nl.appyhapps.healthsync) — известное Android-приложение для синхронизации между экосистемами: Huawei Health, Google Fit, Health Connect, Samsung Health, Garmin, Strava, Polar, Suunto и др. Поддерживает направление Huawei Health → Health Connect. Требует HMS Core на устройстве (для не-HMS-only Android-телефонов с Google-сервисами HMS Core можно доустановить отдельно). На статус-странице проекта отдельно упоминается ограничение «Health Kit not supported in my country» — то есть доступность может зависеть от региона аккаунта Huawei ID; не проверено для конкретной страны пользователя. Разовая платная лицензия (в районе нескольких евро/фунтов, по документации приложения).

### E. Ручной экспорт + Hitrava
Huawei Health app: Me → Account Center (или HUAWEI ID) → Privacy Center → «Request Your Data» → выбрать HUAWEI Health → задать пароль для шифрования архива → подождать (обычно до суток) → скачать ZIP по ссылке из письма (действует 21 день). Внутри — папка с «Motion path detail data» (HiTrack-файлы) — сырые бинарные треки тренировок.

**Hitrava** (github.com/CTHRU/Hitrava, лицензия npsl-3.0, 429 звёзд, последний пуш 2026-07-01, 10 открытых issues) конвертирует эти HiTrack-файлы (включая новый формат ZIP-экспорта 2025 года, судя по changelog) в TCX (для Strava/Garmin), поддерживает бег, велосипед, плавание, ходьбу, хайкинг, кросс-кантри, эллипсоид, кроссфит — с GPS-треком, дистанцией, длительностью, калориями, пульсом и каденсом (где есть в источнике). **Не поддерживает** шаги и сон — только структурированные тренировки. Есть веб-версия без командной строки (Hitrava Web), что снимает часть барьера для нетехнического пользователя, но процесс запроса-ожидания-скачивания-загрузки всё равно многошаговый и не подходит для самостоятельного регулярного использования пожилым человеком без посторонней помощи.

Похожий, но менее живой проект — **aricooperdavis/Huawei-TCX-Converter** (упомянут в поиске, есть issue о том, что данные доступны в чистом JSON без root/бэкапа) — не проверялся подробно, Hitrava выглядит более активным.

### Что уже пробовали для аналогичных задач в Botkin
Ничего специфичного к Huawei в репозитории не найдено. Существующие каналы `apple_health.py` / `android_health.py` принимают уже агрегированные (Apple) или сырые с таймстампами (Health Connect) данные по Bearer-токену `users.health_token` — оба варианта A/B из таблицы выше по формату данных лягут в этот же путь без изменений кода, если мост (Health Sync или Apple-Huawei sync) реально доставит данные до Health Connect/HealthKit.

## Рекомендация

1. **Сначала выяснить у пользователя модель телефона** — без этого нельзя выбрать между путём A (Android+GMS → Health Sync) и путём B (iPhone → встроенный Huawei→Apple Health sync, с оговоркой о ненадёжности тренировок).
2. Если Android с Google-сервисами — предложить установить **Health Sync**, настроить направление Huawei Health → Health Connect, дальше данные должны сами доехать в Botkin через уже работающий `/android_health_v1`. Проверить через неделю, что тренировки реально приходят (сверить `workouts` в БД).
3. Если HMS-only телефон или мост через Health Sync не сработает — как fallback предложить редкий (раз в 1–3 месяца) ручной экспорт через Huawei Privacy Center + Hitrava Web, с чьей-то помощью (не самостоятельно); результат (TCX) можно будет либо загрузить как есть — тогда потребуется парсер TCX в коде Botkin (не сделан, оценка: 0.5–1 день на добавление разбора TCX и записи в `workouts` через существующие raw-SQL пути наравне с Apple/Android webhook'ами, по анти-паттерну проекта — не через ORM) — либо на первое время просто попросить пользователя надиктовывать итоги тренировок из TCX/приложения боту вручную (без кода).
4. Официальный Huawei Health Kit Cloud API (вариант D) — не делать: непропорциональные усилия (регистрация разработчика, OAuth-инфраструктура) ради одного пользователя семейного проекта; пересмотреть только если появится несколько пользователей с Huawei и путь Health Sync окажется массово ненадёжным.
5. Промежуточная мера без ожидания результатов — то, что уже предложено в issue: ручное логирование тренировок голосом боту (уже работает, тул `log_workout`).

## Открытые вопросы к пользователю

- Модель телефона (Android с Google Play или без, либо iPhone)?
- Готов ли пользователь (или кто-то из семьи за него) периодически делать ручной экспорт данных из Huawei, если автоматический мост не сработает?
- Насколько критичны именно GPS-треки/дистанция тренировок, или достаточно факта «была тренировка N минут» (тогда голосовой ввод боту закрывает большую часть потребности уже сейчас)?
