# Аудит обвязки между сообщением пользователя и агентом (ноябрь 2026)

> Статус: исследование, код не менялся. База — ветка `dev` после PR #657–#659 (коммит `4aefc78`).
> Метод: чтение кода, история коммитов и issues, прогон чистых функций маршрутизации на типовых репликах
> локально (`extract_date_from_text`, `_is_clearly_conversational`, `_is_food_mention_in_dialog`).
> Статистику срабатываний с прода не снимали: доступа к прод-БД в этой сессии не было. Цифры цены и задержки
> взяты из ADR-0011 и issue #456.

## 1. Резюме

- Между сообщением и агентом стоят **четыре слоя решений**: регэксп-префильтры, LLM-роутер еды, guard'ы после роутера и детекторы после ответа агента. Каждый слой добавляли заплаткой под конкретный инцидент. Голос и фото идут **другими путями** с другим набором заплаток.
- Корень большинства провалов один: **роутер не видит диалога**. Это промпт парсера еды без истории, с правилом «never answer other for anything edible». Поэтому «у меня есть квашеная капуста» для него запись еды, а guard'ы #198, #514, followup, food-in-dialog и addendum вручную восстанавливают контекст, который роутеру просто не передали.
- Регэксп дат **режет текст до агента и подсказывает ему неверную дату**: «Сегодня чувствую себя плохо после вчерашнего» уходит с директивой «речь про вчера», «3 ноября приём у врача» превращается в 2025-11-03.
- В быстрых путях есть **тихая порча данных**. «вчера 150/95 пульс 70» пишется на сегодня. Голосовое «вес 82,5» отвечает «✅ Записано», но ничего не сохраняет. «забыл выпить омегу» записывается как приём, причём без LLM.
- Предлагаемая рамка — **одно решение на сообщение**. Пока свежий диалог с агентом, ходом владеет агент, а его инструмент записи еды отдаёт ту же карточку-превью. Вне диалога работает роутер, которому передают дату и последний ход. Детерминированный fast-path остаётся только для однозначного структурного ввода: АД без вопроса, фото еды.
- Сервисом остаются сбор данных, карточка превью и кнопки, doc-пайплайн, RLS/JWT, транспортные ретраи, сохранение оплаченного ответа и проактивность. «Врач» — модель поверх тех же инструментов.

## 2. Текущий путь сообщения

```
ТЕКСТ  (handlers/text.py: handle_text_message)
 ├─ state=waiting_description (после фото)?
 │     _is_clearly_conversational → сброс state, дальше по тексту
 │     иначе → photo.handle_description (ветка «ГОЛОС/ПОДПИСЬ» ниже)
 ├─ state=waiting_confirmation → #427 правка превью («без кускуса») → конец
 ├─ 🧪 E2E-маркер, strip_plan_prefix (#407)
 ├─ если НЕ _is_clearly_conversational и НЕ _looks_like_short_value:
 │     extract_date_from_text → ВЫРЕЗАЕТ «вчера/вчерашний/ДД.ММ/29 мая» из text,
 │     custom_date (+ эвристики «вечером→вчера», «23:00 после полуночи→вчера»)
 ├─ #514: от текста осталась одна дата → АГЕНТ
 ├─ #198: короткое число + последний ход агента — вопрос <10 мин → АГЕНТ
 ├─ BP regex (XXX/YY [пульс]) без «?»/диапазона/«было» → save_bp (custom_date ИГНОРИРУЕТСЯ)
 │     с вопросом → save_bp + второй вызов агента за ответом
 ├─ supplement keyword pre-check (≤6 слов, подстрока «омега/магний/…») → vitamins, БЕЗ LLM
 ├─ _is_clearly_conversational («?» / вопросительное слово, нет еды/чисел) → АГЕНТ
 ├─ иначе LLM-роутер analyze_message (Sonnet 5.5, без истории, ~2.6 с p50)
 │     None → regex fallback витаминов / «Не понял… OpenAI не отвечает»
 ├─ guard'ы после роутера:
 │     weight вне 20–400 → other;  bp диапазон/прошлое/нереалистично → other
 │     vitamins: action=metadata → other;  _AGENT_FOLLOWUP_RE + свежий агент → other
 │     food/multi_food + _is_food_mention_in_dialog + агент ≤20 мин → other
 └─ ветки по msg_type: other → АГЕНТ (с директивой о вырезанной дате)
                       food/multi_food/mixed → превью-карточка (кнопки)
                       vitamins/weight/bp/body_measurements → запись сразу

ГОЛОС  (handlers/voice.py)
 transcribe → _is_clearly_conversational ? АГЕНТ
            : state=waiting_description → photo.handle_description
   (нет BP regex, нет #198/#514, нет food-in-dialog, нет extract-date для агента)

ФОТО  (handlers/photo.py: process_photos_list)
 на КАЖДОЕ фото: parse_weight_screenshot (Gemini → GPT-4o) — до роутера
 → analyze_message(фото + подпись)
     vitamins → карточка «записать как приём»; weight → запись; bp → запись
 → есть подпись → handle_description → ВТОРОЙ analyze_message, если не food
       не food: is_medical_document → doc-пайплайн
                иначе архив (кроме _looks_like_health_app_screenshot) → АГЕНТ
                (агент получает ТЕКСТ «Vision прочитала: …», не картинку)
 → нет подписи: is_medical_document → doc-пайплайн,
                иначе «Фото получил, но не распознал еду» (агент не видит вовсе)

АГЕНТ  (core/agent_chat.py: ask_agent)
 system = 📅 дата + meta-промпт + профиль  |  ⏰ время + _recent_tracker_events
 history = _load_history (только source NULL/botkinclaw, 20 строк)
 цикл ≤6 итераций: tool_use → P-003 инвалидация «устаревших» ходов
 финал: пустой → повтор 1 раз; «данных нет» без подтверждения → NO_TOOL_NUDGE;
        «передал разработчикам» без flag_for_devs → NO_DEV_FLAG_NUDGE
```

Сколько LLM-вызовов уходит на типовое сообщение:

| Реплика | Вызовы | Задержка до ответа |
|---|---|---|
| «Обед: гречка 200 г» | роутер | ~2.6 с (p50) |
| «Как я спал?» | агент | 5–15 с |
| «делал зарядку утром» (реплика диалога без «?») | роутер → агент | +2.6 с и ≈$0.006 впустую |
| «170/100 пульс 70, это нормально?» | regex + агент | агент |
| фото Garmin с подписью | weight-OCR → роутер → роутер → агент | 3 лишних vision-вызова |
| фото Garmin без подписи | weight-OCR → роутер | ответ «не распознал еду», агента нет |

Агент стоит $0.047–0.066 за ход (#456), роутер ≈$0.0063 за вызов (ADR-0011).

## 4. Что обязано остаться сервисом и почему

1. **Сбор данных**: синки Garmin/Apple Health/Android/CGM, вебхуки, импорт CSV LibreView. Модель не должна быть в пути потоковых данных: цена, задержка и воспроизводимость.
2. **Быстрый лог с карточкой**: фото или текст еды → превью за секунды → «Сохранить/Отмена», правка до сохранения (#427), слот-пикер, план → факт (#407), справочник продуктов (#255). Ценность — в скорости и в том, что человек видит запись до сохранения. Агент может **вызывать** эту механику, но не заменять её свободным текстом.
3. **Детерминированный АД** для однозначного формата «число/число [пульс] [время]»: ноль LLM и мгновенный ответ, этим путём пользуются пожилые пользователи.
4. **Санитарная валидация** значений (АД 70–250/40–150, вес 20–400) — в слое сохранения, для всех источников, включая инструменты агента.
5. **Doc-пайплайн** (#439/#441, ADR-0010): сохранение документов и извлечение биомаркеров — данные, а не разговор.
6. **Безопасность**: JWT + RLS по cohort для инструментов, admin-only инструменты, MCP с PAT (ADR-0006).
7. **Надёжность транспорта**: ретраи и fallback-модель, восстановление при 400, повтор пустого хода, закрытие транзакции до сети (#347), сохранение оплаченного ответа при сбое БД.
8. **Инжекция даты и времени** пользователя в system агента — опора, на которой модель считает относительные даты.
9. **Проактивность**: напоминания о еде и добавках, план → факт, уведомления по фидбеку — по расписанию, без модели в цикле.
10. **Проверяемые факт-гейты** с нулём ложных срабатываний по конструкции: «утверждает действие X, а инструмент X не вызван» (dev-flag), «утверждает отсутствие данных при нуле вызовов» (#477 в исходной форме).
11. **E2E-маркер 🧪** и `source`-разметка: нужны для чистки тестовых данных и ночного review.

## 5. План: шесть задач по порядку

Порядок: сначала дешёвые починки тихой порчи данных, затем единый вход, затем режим диалога (он снимает больше всего заплаток), затем роутер с контекстом, потом история и детекторы. Каждую задачу проверять E2E на дев-стенде реальной репликой.

### Задача 1. Починить тихую порчу данных в быстрых путях (без смены архитектуры)
- BP regex и ветки weight/vitamins: передавать `custom_date` в `save_bp_to_db` / `save_weight_to_db` / `save_supplements` (сейчас дата теряется).
- `handle_description` (photo.py:1408): ветка weight должна сохранять, а не только отвечать «Записано»; vitamins — с датой и проверкой `action=metadata`.
- Убрать supplement keyword pre-check (text.py:1083–1142): решение — за роутером.
- `extract_date_from_text`: не сдвигать будущую дату текущего месяца на прошлый год; «вчерашн\w*» не применять при явном «сегодня» в тексте.
- Удалить мёртвые guard'ы внутри веток weight/bp и неиспользуемую `tool_called_this_turn` (или использовать в задаче 6).

**E2E:**
- «вчера 150/95 пульс 70» → запись АД со вчерашней датой и ответ «записал на вчера».
- голосом «вес 82,5» → запись в `body_measurements`, в `/day` виден вес.
- «забыл выпить омегу» → в `supplements_log` нет приёма, ответ агента по сути.
- «Сегодня чувствую себя плохо после вчерашнего» → агент разбирает сегодняшний день, директивы «речь про вчера» во входе агента нет (лог `agent_chat`).

### Задача 2. Единый вход для текста, голоса и подписи к фото
Вынести из `handle_text_message` функцию `route_text(user_id, text, source)` и звать её после транскрипции голоса и для текста в `waiting_description`. Голос перестаёт ходить в `handle_description` напрямую.

**E2E:**
- в свежем диалоге с агентом голосом «вчера выпил пару бокалов шампанского» → ответ агента по сути и одна фраза «записать?», без карточки еды.
- голосом «151/92 пульс 65» → запись АД без LLM, как текстом.

### Задача 3. Режим диалога: в свежем диалоге ходом владеет агент
- Одна функция `dialog_active(user_id, minutes=20)`: последний assistant-ход — агент (`botkinclaw`). Если да, текст сразу идёт агенту, роутер не зовётся. Исключения: строгий BP-формат без вопроса и state'ы карточек (#427).
- Агенту — запись еды с превью: `log_meal_text(..., preview=true)` возвращает черновик, бот рисует **ту же** карточку с кнопками (`meal_preview.py`). Добавить `log_weight`, сейчас его у агента нет.
- Удалить #198, #514, `_ADDENDUM_RE`, `_AGENT_FOLLOWUP_RE`, `_is_food_mention_in_dialog`, `agent_last_turn_was_question`.

**E2E:**
- агент спросил «Сколько весишь?», пользователь «82,5» → агент записывает вес через `log_weight` и подтверждает.
- в диалоге о самочувствии «у меня есть квашеная капуста» → совет по сути (рассол — рюмка), без карточки.
- в диалоге «запиши: на обед гречка 200 г и котлета» → карточка «Сохранить/Отмена» с КБЖУ, как у быстрого пути.
- вне диалога (агент молчит >20 мин) «Обед: гречка 200 г» → карточка за ≤3–4 с без вызова агента (лог: нет `agent_chat`).

### Задача 4. Роутер вне диалога: дата и время на входе, без вырезания текста
- В `analyze_message` передавать некэшируемым блоком текущие дату и время пользователя. Роутер возвращает `date`/`time` для food/bp/weight/vitamins. Убрать поле `reply` у `other`.
- Агенту текст передавать **без** `extract_date_from_text`. `_agent_text_with_date_hint` удалить. Регэксп дат оставить fallback'ом для BP regex.
- Перенести прецеденты (#629, «вечером → вчера», «Обед вчера: …») в eval роутера `scripts/eval/`, прогнать до и после.

**E2E:**
- «У меня 3 ноября приём у врача, что спросить?» → агент готовит вопросы к визиту 03.11 текущего года.
- отправить в 00:40 «ел в 23:00 творог 200 г» → карточка с датой вчера и временем 23:00 (регресс #629).
- в 07:40 «вечером выпила 500 мл кефира» → запись на вчерашний вечер.
- «вчера крутил велотренажёр 40 минут» → тренировка на вчера (регресс #510).

### Задача 5. Парсерные записи — в историю агента, а не отдельным блоком
- Быстрые пути пишут в `agent_conversations` пару: user-текст и assistant «✅ записал <что> на <дату время>» с source, который `_load_history` берёт.
- Удалить `_recent_tracker_events` и `_inject_bp_to_agent_conv`. Проверить, что агент не отвечает повторно на записанное и не дублирует запись.

**E2E:**
- записать «130/85 пульс 62» (regex-путь), затем спросить «какое у меня было давление сегодня?» → агент вызывает `get_recent_bp` и называет 130/85, без «ты не вносил».
- «выпил бокал вина» (карточка сохранена), через 2 минуты «почему пульс высокий?» → агент говорит «ты только что выпил вино», а не «пару дней назад».

### Задача 6. Детекторы агента и фото: сузить и проверить eval'ом
- #477: нудж только при нуле вызовов инструментов в ходе (`tool_called_this_turn`); ветку «вызывал, но ничего пустого» убрать.
- P-003: прогнать на выборке диалогов (#456: eval с эталоном). Если срабатываний на пользу нет — выключить флагом, затем удалить.
- Фото: роутер возвращает подтип `health_app_screen`. Такие фото с подписью и без уходят агенту **с картинкой**. Убрать `parse_weight_screenshot` до роутера и второй вызов роутера в `handle_description`.
- Секцию «САМОЧУВСТВИЕ» в meta-промпте свести к принципам, частные советы проверять eval'ом.

**E2E:**
- «почему вчера был высокий стресс?» в день, когда часы снимали → один полный разбор с хронологией, в `agent_conversations` нет `botkinclaw_nudged`.
- скрин Garmin «Отклонений: 2» **без подписи** → агент разбирает показатели со скрина и сверяет с `get_intraday_timeline`, фото не в архиве документов.
- фото тарелки → карточка; в логе один vision-вызов роутера, без weight-OCR.
