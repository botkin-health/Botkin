# ADR-0010: Разбор медицинских документов — Sonnet 5, дата взятия, тип и резюме документа

**Дата:** 2026-09-25 · **Статус:** принято · **Автор:** Александр Лысковский (с Claude) · **Issue:** #558

## Контекст

24.09.2026 пользователь (external) загрузил через `/doc` ~20 страниц анализов, УЗИ и
гинекологических мазков. При ручном разборе нашлись системные дефекты
`core/health/doc_extractor.py` (Haiku 4.5):

- в половине страниц бралась **«Дата печати»** вместо «Даты взятия материала» — анализ
  ложился в динамику на 11 дней позже; дважды неверно прочитан год (2025, 2028);
- у мазков и ПЦР модель выдумывала числа под ключи вроде `leukocytes`
  («1–2 в п/зр» → 1.2, «> 50000 клеток в образце» → 50000), а качественные результаты
  («не обнаружено») не сохранялись вовсе;
- «Z01.4 — гинекологическое обследование» попадал в медпрофиль как хронический диагноз;
- «Витамин B12 активный» (холотранскобаламин, норма 25–165 пмоль/л) писался как
  `vitamin_B12` и канонизировался в пг/мл общего B12 — выглядел тяжёлым дефицитом;
  СРБ в мг/дл не пересчитывался в канонические мг/л;
- повторные фотографии того же бланка сохранялись дублями (дедуп — только по хэшу файла).

## Что мерили

`scripts/eval/doc_extractor_eval.py` — прогон экстрактора по папке бланков и сверка с
эталоном, размеченным вручную по самим фото: 23 страницы (анализы крови, УЗИ ОБП/почек/
малого таза, мазки/ПЦР/цитология, заключение врача, 10 пар повторных снимков). Данные —
личные, лежат только на сервере в `data/eval/doc/` (gitignored). Прогон с прод-сервера
(как в ADR-0009), код ветки — копией в `data/eval/doc/code/`.

Метрики: дата верна / взята дата печати, `doc_kind` верен, мазки без чисел, есть резюме,
коды Z в диагнозах, реальные диагнозы не потеряны, активный B12 и СРБ в мг/л, строка в
`blood_tests` у нелабораторного документа, пойманы ли повторные снимки (и ложные
срабатывания), латентность p50, $/документ.

Из 14/23 у Sonnet 5 на старом промпте 8 промахов — не ошибки чтения, а сорвавшийся
разбор ответа (см. «Грабли»). Haiku и на новом промпте путает день/месяц в «08.09.2026»,
не отдаёт единицы для СРБ и дважды ошибается в типе документа.

## Решение

1. **Модель — `claude-sonnet-5`**, в `config/models.py` как `DOC_EXTRACT_MODEL`
   (override `BOTKIN_DOC_EXTRACT_MODEL`). Объём ~40 документов/мес → разница с Haiku
   < $0.5/мес; латентность +1.5 с при уже показанном пользователю «Читаю…» приемлема.
   Расходы теперь пишутся в `llm_usage_log` (purpose `doc_extract`) — раньше не писались.
2. **Дата** — приоритет «дата взятия / забора / исследования / приёма», запрет на даты
   печати/выдачи/регистрации/готовности; модель отдаёт `date_label`, код
   (`_sanitize_date`) отбрасывает не-ISO, будущие и помеченные как печать даты
   (`_date_rejected`). Дату не угадываем.
3. **Тип и резюме** — `doc_kind` (`lab_panel` / `imaging` / `smear_pcr` / `doctor_note` /
   `other`), `doc_type` (существующее поле названия, раньше не заполнялось) и `summary` с
   качественными результатами. У `smear_pcr` числа отбрасываются кодом
   (`_dropped_values`); `doc_to_blood_test` не пишет строку для `smear_pcr`/`other`.
   **У `lab_panel` резюме не хранится** (`summary = null`): модель пишет «все показатели
   в пределах нормы» и при значениях выше нормы, в каждый раз новой формулировке
   (проверка на дев-стенде: «в пределах указанных референсных значений» при RBC выше
   нормы). Фильтр оценочных фраз прошёл 4 итерации и каждый раз пропускал новую —
   отвергнут в пользу простого правила. Значения лежат в `values`, оценка — у агента.
4. **Диагнозы** — коды Z00–Z13 (осмотры, обследования, скрининг) фильтруются
   детерминированно (`_dropped_conditions`). Остальные Z — значимые состояния (Z95 стент,
   Z94 трансплантат, Z99.2 диализ, Z21, Z34 беременность, Z79 длительная терапия) —
   остаются: фильтр на весь Z00–Z99 скрыл бы их от агента (ревью PR #560).
5. **Аналиты и единицы** — канонический `holotranscobalamin` (пмоль/л); модель отдаёт
   `units`, `_convert_units` пересчитывает только известные несовпадения (CRP/hs_CRP
   мг/дл → мг/л); незнакомые не «чинит» молча.
6. **Дубли** — `core/health/doc_duplicates.find_similar_document`: ≥80% из ≥3 чисел при
   совместимой дате, либо та же дата + `doc_kind` + сходство резюме и названия ≥ 0.3.
   Порог — по данным (повторные снимки 0.36–0.95, разные страницы за тот же день ≤ 0.23).
   Только предупреждение в превью — решает пользователь.

7. **Сводные документы с несколькими датами (#559)** — таблица «дата × показатели»
   (досье, выписка «в динамике») отдаётся полем `series`: по записи на дату со своими
   значениями и лабораторией, верхние `date`/`values` пусты. `_normalize_series`
   отбрасывает строки без полной ISO-даты («03.2023» не превращается в 1 марта) и с
   будущей датой (`_series_rejected`), склеивает записи одной даты; одна дата —
   обычный документ, `series` не остаётся. В `blood_tests` — строка на дату
   (`doc_to_blood_test.build_blood_test_rows`), ключ upsert'а тот же, поэтому
   перезалив досье обновляет строки. Текстовый PDF длиннее 12 тыс. символов режется
   по страницам на части ≤ 3.5 тыс. (≈ страница) и разбирается параллельно (не больше
   6 вызовов одновременно), части склеиваются по датам (`merge_extractions`); обычные бланки
   (≤ 4.2 тыс. символов у всех пользователей на 26.09.2026) идут одним вызовом, потому
   что страница-продолжение без даты при разрезе теряла бы дату первой страницы.
   Страниц PDF читается до 40 (было 10 — хвост досье пропадал молча).

## Грабли (Known issues)

- **Sonnet 5 начинает ответ с блока `thinking`.** `content[0]["text"]` падал `KeyError`,
  и документ молча превращался в `{}`. Теперь склеиваются все текстовые блоки.
- **`thinking` тратит тот же `max_tokens`.** На 2048 длинное УЗИ обрывалось посреди JSON.
  Лимит 4096, `stop_reason=max_tokens` пишет warning. Тайм-аут запроса 60 → 180 с.
- **Выборка маленькая** (23 страницы одного пользователя, одна лаборатория и клиника).
  Порог сходства дублей и правила дат стоит перепроверить на новых бланках; эталон
  пополнять ручной разметкой, не подтверждёнными ответами прода (урок ADR-0009).

- **Длинный документ — минуты.** Sonnet 5 думает ~70 с над каждой плотной страницей
  таблицы. 15-страничное досье (36 тыс. символов): части по 8 тыс. и лимит 8192 — 3 из
  5 частей пустые (весь лимит ушёл в thinking, JSON не начался); части ≈ страница и
  лимит 16000 — 15/15, 60 дат, 23 строки анализов, но 363 с при 3 параллельных.
  Параллельность поднята до 6, пользователь видит «длинный документ — пару минут».

## Отвергнуто

- **Одна строка `blood_tests` на сводную таблицу с датой последнего столбца** — так
  работал старый разбор: показатели 2016 и 2026 годов лежали в динамике одним днём.
- **Дедуп досье с первичными бланками по дате** — бланк за 14.07, чьи числа есть в
  досье, дублем не считается (сравнение только «новое ⊂ старое»): бланк — первичный
  документ, досье — пересказ. Одинаковое значение за один день из двух документов в
  динамике допустимо.

- **Оставить Haiku 4.5 ради цены** — экономия < $0.5/мес против неверной даты у каждой
  шестой страницы и неверного пересчёта единиц.
- **Точное совпадение названия для дублей** — модель по-разному формулирует название
  одной и той же страницы с двух фото (3/10 пойманных против 10/10).
- **Сверять дату с текстом документа для фото** — текста нет (vision); сверка возможна
  только для PDF с текстовым слоем, и там она диагностическая.

## Открыто / follow-up

- Сканированный PDF разбирается только по первой странице (`max_pages=1`).
- Существующие документы, разобранные до #558, не переразбираются автоматически.
- Сводная таблица со сканом вместо текстового слоя — только первая страница (как любой
  скан). Разбивка на части — только по страницам: одна страница > 3.5 тыс. символов идёт
  одним вызовом.
