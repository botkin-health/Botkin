# ADR-0009: Парсинг еды — Sonnet 5 + короткий промпт, выбор по eval на реальных кейсах

**Дата:** 2026-09-13 · **Статус:** принято · **Автор:** Александр Лысковский (с Claude)

## Контекст

12.09.2026 закончился баланс Anthropic API — BotkinClaw и разбор еды молчали у всех
пользователей. Разбор трат по `llm_usage_log` за 30 дней: блок «еда»
(`food_text` + `food_photo`) — **$16/мес, 64% всего счёта**, при этом 60% этих денег —
запись в кэш системного промпта (37K символов ≈ 5.9K токенов, летит на каждое
«стакан воды»). Латентность прода: p50 **6.3 с**, p90 **10.9 с** — заметная пауза в чате.

Кандидаты: Haiku 4.5 (3× дешевле), Sonnet 5 (новее, −23%), Gemini 3.x Flash,
GPT-5-mini/nano, урезанный промпт, регекс-предфильтры, self-hosted food recognition.

## Что мерили

Эталонного набора не было; «золотые» ответы из `food_interactions` (то, что прод распознал
и пользователь подтвердил) оказались смещены в пользу прод-модели и местами ошибочны
(«стакан воды» = 38 ккал, молоко 200 мл 1.5% = 46 ккал).

Собран замороженный набор **111 реальных кейсов** (`scripts/eval/build_food_eval_set.py`):
40 текстов, 47 фото (11 карточек Elementaree, 18 этикеток/скриншотов КБЖУ, еда на весах,
тарелки), 16 мед. документов из `/doc`, 8 синтетических «не еда» (давление, вес, витамины).
Эталон `scripts/eval/golden_v3.json` составлен вручную по трём уровням: **точный**
(печатный итог карточки, таблица КБЖУ на упаковке, вес пользователя × справочник),
**интервал** (тарелки без веса), **только тип** (медицина, давление, вес).
Метрика — попадание ккал/белка в интервал, совпадение типа/подтипа, латентность, $/вызов.
Прогон — с прод-сервера (Hetzner, Германия), `scripts/eval/food_parsing_eval.py` +
`rescore.py`.

## Решение

1. **Модель разбора еды — `claude-sonnet-5`** (`config/models.py`, override
   `BOTKIN_FOOD_TEXT_MODEL`). Sonnet 5 отвергает `temperature` → роутер гейтит
   sampling-параметры по семейству модели (`_is_claude_4x`).
2. **Системный промпт v2** — `core/llm/prompts/food_router_system.txt`, ~11.7K символов
   (−69%). Сохранены все правила из инцидентов (CASE B + MODIFIER для meal-kit карточек,
   независимые веса в одном сообщении, multi_food, весы, zero-напитки) — их фиксируют
   `tests/test_router_prompt_rules.py`, `tests/test_multi_food.py`. Промпт v1 (без явного
   «карточка-рецепт = еда» и без определений мед. подтипов) провалил карточки и
   `medical.subtype` — эти два блока добавлены в v2.
3. **Haiku 4.5 отвергнут**: не читает карточки Elementaree (27%) и таблицы КБЖУ (19%).
4. **Смена провайдера отложена до октября 2026** (переезд в ОАЭ, доступ к API без
   гео-блоков). GPT-5-mini на порядок дешевле, но −25 п.п. по ккал; Gemini free-tier
   в проде недопустим для медданных (обучение на данных, лимит 15 RPM) — см. п. «Открыто».

Ожидаемый эффект на блоке «еда»: **−48% $/вызов, −43% латентности p50**, качество не ниже.
Контрфакт по `llm_usage_log` с 20.05.2026: $55.65 → ~$18.5 (`scripts/eval/cost_retrospective.py`).

## Отвергнуто

- **1-часовой TTL кэша** — по реальным промежуткам между вызовами (60% хитов на 5 мин,
  78% на 1 ч) выигрыш ~7% при записи 2×; не стоит.
- **Self-hosted food recognition** (Nutrition5k, FoodLMM) — американская кухня,
  research-код, нужен GPU; при ~17 вызовах/день ROI отрицательный.
- **Подписка Claude вместо API для сервера** — нарушение Consumer Terms.
- **Ресайз фото** — Telegram уже ужимает до 1280px, картинка ~1.4K токенов.

## Открыто / follow-up

- Ключ Gemini в проде — **free tier** (`generate_content_free_tier_requests, limit: 15`):
  OCR весов и fallback еды идут в Google на условиях обучения на данных. Перевести на
  платный тариф или убрать из цепочки.
- Агент BotkinClaw — $67 из $123 за 4 месяца; следующая волна оптимизации.
- Систематические промахи обеих Sonnet: безлактозное молоко 1.5% (дают 46–60 вместо
  ~88 ккал), Exponenta High-Pro 250 г (занижают порцию) — кандидаты в якоря промпта.
- Eval гоняется вручную; можно повесить на CI как nightly с бюджетом ~$1.
